# 技术设计建议

下列是待实现设计，不是当前源码能力。沿用 Python 3.11 x64 + PySide6，最终 PyInstaller Windows onedir 发布。若 Qt 包体成为明确约束，再评估原生 Win32/C#；不在第一版中途无故重写技术栈。

## 窗口和渲染

每位一个顶层 QWidget，透明、无边框、置顶、Qt.Tool；不使用网页窗口。默认角色画布 240×280 逻辑像素，顶部另外预留约 80 像素气泡区；布局根据文字实测调整。开启高质量绘制，保持纵横比，不拉伸角色。

窗口位置固定在基础坐标，呼吸浮动只改变绘制位置，幅度约 2～3 逻辑像素。睡眠时幅度减小；拖动时暂停浮动。缓存帧，不在每次 paintEvent 重新读文件。常态目标 20～30 FPS，可进一步减少无变化时重绘。

透明像素不一定自动鼠标穿透。需要基于 alpha 的命中区域或 Windows 命中测试实现：只让角色和可见气泡拦截点击；掩模包含浮动范围。验证高 DPI 下坐标映射和透明边缘，不能通过把整个窗口设为穿透来破坏拖动。Windows 具体方案通过实测选定。

## 点击和拖动

1. 左键按下保存全局位置、窗口位置，尚不触发对白。
2. 按住移动，距离超过 QApplication.startDragDistance() 才进入拖动态。
3. 用全局逻辑坐标计算目标位置；只改变当前角色。
4. 左键释放：如果没有形成拖动，触发一次点击；否则保存位置。
5. 右键仅打开菜单；丢失鼠标捕获或窗口隐藏时清除拖动标记。

## 状态机

| 当前状态/事件 | 行为 | 结束条件 |
| --- | --- | --- |
| idle | 微呼吸，安排随机眨眼 | 点击、手动状态、空闲超时 |
| idle + 眨眼截止 | half→closed→half | 约 160～240 ms 后返回 idle |
| 单击 | 显示对白、进入 cute | 约 2 秒回 idle |
| sleep + 单击 | 唤醒并说早安/醒来对白 | cute 后回 idle |
| 无操作 180 秒 | sleep | 点击或手动唤醒 |
| 右键睡觉 | sleep | 点击或手动唤醒 |
| 右键待机 | idle 并重新安排眨眼 | 正常事件 |
| 隐藏 | 暂停动画与计时推进 | 显示时重新建立时间基准 |

眨眼间隔建议随机 3～7 秒；气泡约 4 秒；可配置。每只独立保存状态，sleep 不应被定时眨眼唤醒，cute 期间不插入 blink。用户操作优先级高于自动动作。使用 monotonic 或 QElapsedTimer，避免系统时间变化和积压 timer 导致状态错乱。

基础帧 idle 缺失应报告可读错误；非必需帧缺失可以回退 idle 并记录日志。正式发布必须拥有全部四类必需帧，不能靠回退蒙混验收。

## 菜单与可恢复性

角色菜单：角色名称、说句话、表情/动作、大小、隐藏这只、显示另一只、显示全部、恢复位置、退出。

托盘菜单：550G 子菜单、前辈GPT 子菜单、显示全部、隐藏全部、恢复主屏位置、关于、退出。每只子菜单支持显示/隐藏及动作。双击托盘显示全部，首次提示恢复方法。

无托盘时显示小型控制窗口，隐藏所有宠物后该入口仍可见。若控制窗口无法建立，则禁用“隐藏最后一个可见入口”的动作。系统托盘溢出区不等于托盘不可用，需要提示用户查看隐藏图标。

## 配置、多屏与持久化

用 QStandardPaths 的 AppConfigLocation / AppLocalDataLocation；配置不写在安装目录。保存 schema_version、每只位置、缩放与偏好。配置损坏或版本不支持则用默认值并记录问题，采用临时文件加原子替换写入。

保存角色区域的坐标；恢复时按 QScreen.availableGeometry 检查，不能用 x/y<0 就认定离屏，因为左侧显示器可以是负坐标。若角色主要区域不与任一屏可用区域相交，移回主屏安全边距。显示器拔插、工作区变化时重新校验。“恢复位置”始终可用。

重启默认显示两只，避免把上次全部隐藏变成启动无反应。大小恢复但不允许异常值导致巨型或零尺寸窗口。气泡靠边时需内部换位或整体调整，不能被屏幕截断。

## 生命周期与错误

用 QLockFile 或等效机制阻止重复实例，并用 QLocalServer/QLocalSocket 通知已有实例显示全部。处理陈旧锁、启动竞争和失败反馈，避免单纯锁住导致用户无法找回隐藏角色。

隐藏不退出；退出停止计时、保存配置、隐藏托盘并结束事件循环。QMenu、QAction 和托盘持有稳定生命周期，避免被垃圾回收。日志记录异常及版本，不记录用户桌面内容。纯本地离线对白，不调用外部模型。

## 资源和打包路径

统一 resource_path()，源码相对模块路径，冻结包从随包资源目录加载（依据实际 PyInstaller 模式实现）。不要依赖当前工作目录。文件缺失要给出路径和清楚的错误；日志路径可被用户找到。

## 关键测试

单元测试状态转换/时序优先级、屏幕约束含负坐标、配置损坏回退、资源解析。Qt 测试点击/拖动阈值和菜单路由。Windows 实机检查透明、置顶、托盘、DPI、多屏、冻结包。离屏测试只能证明部分逻辑，不能替代原生桌面验收。
