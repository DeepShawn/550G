# Windows 构建与交付

以下是后续执行指南，尚未执行 Windows 构建。不要从本 Linux 工作区产生的可执行文件声称已得到 Windows EXE。

## 开发环境和原版启动

推荐 Windows 10/11 x64，Python 3.11 x64。在交接包根目录用 PowerShell：

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r .\source_original\requirements.txt
.\.venv\Scripts\python.exe .\source_original\main.py
```

保留原始目录作为基线，复制到 app_work 后开发。原 BAT 每次启动会联网检查/安装依赖，不适合最终发布。新开发启动脚本应识别环境、明确安装错误，只在依赖缺失时安装；不要盲目调用系统中不确定的 Python 版本。

## 构建策略

先 onedir，再按需要评估 onefile。onedir 有利于资源和 Qt 插件排错，避免每次解压 onefile 的启动成本。最终用户必须解压整个目录，不能只复制 EXE。

以下命令只适合验证原型打包路线，仍然使用旧 SVG，不是最终版本：

```powershell
.\.venv\Scripts\python.exe -m pip install "pyinstaller>=6,<7"
.\.venv\Scripts\python.exe -m PyInstaller --noconfirm --clean --windowed --onedir --name DesktopPets550G --add-data "source_original/assets:assets" .\source_original\main.py
```

在实际使用的 PyInstaller 6 版本检查 --add-data 语法，构建完成后从 `dist/DesktopPets550G/DesktopPets550G.exe` 验证。新项目接入 PNG、ICO、对白等资源后编写并提交 windows.spec，所有必要资源列入 datas，托盘 ICO 和 EXE 图标明确指定。调试问题时先做 console 构建，稳定后切换 windowed；无控制台版本仍需持久日志和错误提示。

## 可复现构建

1. 使用干净虚拟环境，不复用含无关包的个人环境。
2. 记录 Python 小版本、Windows 版本、Qt/PySide6/PyInstaller 版本。
3. Windows 验证成功后锁定运行依赖和构建依赖，提交锁文件。
4. 固定版本号，清理旧 dist/build，从同一源码构建。
5. 在无 Python 的独立机器或虚拟机运行全部发布阻断用例。
6. 生成发布文件 SHA-256，与对应源码版本一起记录。

Qt/PySide6 体积需要实测，不承诺极小安装包。分发前包含适用的第三方许可证和组件清单，素材也保留来源记录。

## 最终发布目录建议

```text
550G_GPT_DesktopPets_v0.2.0_win_x64/
  DesktopPets550G.exe
  _internal/                 # PyInstaller 实际产物，整体保留
  使用说明.txt
  CHANGELOG.md
  THIRD_PARTY_NOTICES.txt
  已知限制与测试记录.md
```

资源实际位置由 spec 决定，不手工移动冻结包内文件。源代码 ZIP 另发，不把 .venv 和构建缓存塞给用户。

## 用户说明必须覆盖

- 解压整个目录，双击 EXE。
- 左键点击说话、按住拖动；右键选择表情、大小、隐藏和退出。
- 从任务栏托盘或隐藏图标区恢复；双击托盘显示两只。
- 离屏时使用恢复位置；配置和日志实际路径。
- 首版是离线预设对白，无联网 AI 或语音。
- 明确已验证 Windows 版本与未解决限制；未签名包可能出现系统提示，应如实说明签名状态，不指导关闭安全软件。

## 发布完成前检查

必须看到实际启动的 EXE，而不只是“构建成功”；核对无 Python、断网、中文路径、普通权限、退出无残留。未通过时交付明确标注的开发预览，并列出阻断项，不宣称正式完成。
